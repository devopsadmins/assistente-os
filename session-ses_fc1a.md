## 字幕生成 📜

[](#字幕生成-)

当前支持两种字幕生成方式：

-   **edge**：使用 TTS 时间戳生成字幕，速度快，不需要 GPU，默认使用该模式。
-   **whisper**：使用本地 `faster-whisper` 转写音频，适用于需要更准确字幕时间轴的场景。首次使用时需要下载模型。

在 `config.toml` 中修改 `subtitle_provider` 即可切换模式。Whisper 默认使用约 3 GB 的 `large-v3`；如需更小、更快的模型，可以使用约 1.6 GB 的 `large-v3-turbo`：

\[app\]
subtitle\_provider = "whisper"

\[whisper\]

## 3. What's Missing or Could Be Enhanced

### Critical Enhancements:

1. **Web UI / Dashboard** — While LangGraph UI exists at `packages/daemon/web/index.html`, there's no integrated web dashboard. The CLI and MCP are the primary interfaces; a web UI would improve accessibility.

   - Full docker-compose with Postgres + Ollama services
   - Health check endpoints
   - Deployment scripts for production

3. **API Documentation** — No OpenAPI/Swagger specs for the daemon's REST endpoints. Auto-generation would help both internal and external consumers.

4. **Rate limiting & throttling** — Daemon API has no apparent rate limiting. Could add per-soul or global rate limiting, especially for the MCP endpoints.

5. **Caching strategy** — RAG operations could benefit from more aggressive caching (embedding cache, search result cache) to reduce LLM calls and costs.

6. **Configuration validation** — `loadConfig()` silently defaults missing values. Could add schema validation (e.g., using AJV or Zod) to catch misconfigurations early.

7. **Error handling consistency** — Some tools throw errors that propagate up; could standardize error responses across MCP, CLI, and daemon.

8. **Tests coverage** — Looking at the test structure:
   - Unit tests exist in `packages/*/src/test/` and `packages/*/dist/test/`
   - Some integration tests require Postgres + pgvector
   - Live tests (`.live.ts`) need a running daemon
   - Could improve test coverage and make non-DB tests more robust

9. **Multi-tenancy support** — Current design uses "souls" as units, but could add proper multi-tenant isolation with per-tenant databases/configurations.

10. **Search pagination** — RAG search and graph listings could support pagination for large result sets.

11. **Backup format options** — Backup is ZIP-only; could add incremental backups, compressed formats, or cloud storage integration (S3, R1).

12. **Real-time features** — WebSocket events could be expanded (currently basic support; could add presence, typing indicators, etc.)

13. **Model selector UI** — The router has fast/pro modes, but could add a UI to select/configure models per soul.

14. **Observability** — Basic pino logging exists; could add:
    - Metrics export (Prometheus)

15. **WhatsApp business features** — Baileys integration exists but could add:
    - Template messages

16. **Environment variable management** — `.env` loading is basic; could add:
    - Validation of required vars

17. **CLI command completeness** — Some features have web/MCP alternatives but not CLI shortcuts (e.g., guardian rule management via CLI is complete, but some advanced features may be missing).

18. **Schema documentation** — Soul config format, relevance rules, and guardrail structures aren't well documented outside the code.

19. **Long-term memory persistence** — While LangGraph checkpoints exist, could add explicit export/import of agent states for recovery.

Cache em camadas com as seguintes características:

| Layer | Descrição |
|-------|-----------|
| **Redis** | Primary cache - persistente, compartilhado entre instâncias |
| **Map Memory** | Fallback local - acesso rápido quando Redis cair |
| **SQLite kernel.db** | Tertiary - para dados que precisam de queries indexadas |

### 2. Métodos Implementados

| Método | Descrição |
|--------|-----------|
| `cache.init()` | Inicializa conexão Redis com fallback graceful |
| `cache.get(key)` | Busca: Redis → Memória |
| `cache.set(key, value, ttl?)` | Escreve: Redis + Memória com TTL |
| `cache.del(key)` | Remove chave específica |
| `cache.getEmbedding(textoHash)` | Cache de embeddings: hash → vetor |
| `cache.setEmbedding(textoHash, vector)` | Armazena embedding com TTL 1 semana |
| `cache.getRagResults(queryHash)` | Cache de resultados RAG: query → results |
| `cache.setRagResults(queryHash, results)` | Armazena RAG results com TTL 1 hora |
| `cache.isRedisAvailable()` | Verifica se Redis está up |
| `cache.getStatus()` | Retorna status (redis, memoryEntries, redisUrl) |

### 3. Configuração de Ambiente
- `REDIS_URL` - URL do servidor Redis (padrão: `redis://localhost:6379`)
- `ASSISTENTE_OS_CACHE_MAX_ENTRIES` - limite de entradas em memória (padrão: 1000)

### 4. Exportação
