Hardware & Quantization Trade-offs
32GB RAM (e.g., Apple Silicon M-series Air/Pro):
 Can comfortably run a 
4-bit quantization
 (such as 
Qwen3.8-27B-MLX-4bit
), reaching 
98.6% accuracy
 on the benchmark.
16GB RAM (e.g., base M1 Pro or discrete 16GB GPUs):
 Requires a 
3-bit quantization
 (such as 
IQ3_XXS
), achieving 
96.4% accuracy
 at ~5 tokens/second.
Macs with unified memory and high GPU memory bandwidth provide distinct advantages for running 27B-parameter weights locally.
Inference Acceleration via MTP (Multi-Token Prediction)
Multi-token prediction functions like CPU branch prediction—speculatively generating tokens and verifying them against the main model (risk-free accuracy).
On newer chips with high memory bandwidth, MTP provided a 
~30% speed boost
 with draft size 3.
On older hardware (e.g., M1 Pro with 16GB), MTP created computational overhead and actually reduced net tokens per second.
How the Stack Works
Local Database:
 DuckDB acts as the in-process execution engine, allowing agents to execute exploratory queries, inspect schemas, and query local Parquet/CSV files with zero server overhead.
Serving Layer:
 LM Studio serves Qwen3.8 via an OpenAI-compatible local endpoint (
localhost:1234
), typically configured with a 16k context window and low reasoning effort.
Agent Harness:
 Tools like OpenCode or custom LangChain/LangGraph agent harnesses interact with DuckDB through tool-calling loops (iterating on syntax errors, inspecting tables, and aggregating answers).
Cloud Scaling:
 Workloads can be offloaded seamlessly to 
MotherDuck
 by adjusting the connection string when datasets exceed local disk/memory limits.
